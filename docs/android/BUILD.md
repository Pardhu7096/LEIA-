# Reproducible Android builds (LEIA Agent CRM and Customer App)

Both apps are Expo SDK 58 / React Native 0.88.1 projects. Their `android/` folders are generated by `expo prebuild` and are not committed. Everything needed to regenerate them is in Git:
- `agent-app/app.json`, `frontend/app.json` (identity)
- the lockfiles
- `scripts/android/toolchain.json` (pinned tools)

## Build
```powershell
cd D:\LEIA                      # any clone; the build always uses a clean git archive of -Commit
git fetch origin
.\scripts\android\build-customer.ps1 -Commit <sha> -ApiUrl https://leia-backend-staging.onrender.com -DryRun
.\scripts\android\build-customer.ps1 -Commit <sha> -ApiUrl https://leia-backend-staging.onrender.com
.\scripts\android\build-agent.ps1    -Commit <sha> -ApiUrl https://leia-backend-staging.onrender.com
```
The script:
1. Refuses to start unless Java, Node, the SDK, NDK and CMake match the pins.
2. Exports the app folder from the exact commit (`git archive`) into `D:\LB\<app>-<sha7>-<UTC>`. The short path avoids the Windows long-path CMake/ninja failures seen on 2026-11-23.
3. Checks `app.json` identity and versionCode, and checks the lockfile pins.
4. `npm ci`, then `expo prebuild --platform android --clean`, then verifies the Gradle wrapper URL and adds its pinned SHA-256.
5. `gradlew :app:assembleRelease -PreactNativeArchitectures=arm64-v8a`, with `EXPO_PUBLIC_API_URL` set to `-ApiUrl`.
6. Verifies the APK: id, versionCode, label, SDK levels, ABI, **no background-location permission**, signature, expected signer fingerprint, and the baked API host.
7. Copies the APK, `mapping.txt`, `build.log`, `SHA256SUMS` and `build-manifest.json` to `D:\LEIA-Releases\builds\<app>\<version>-vc<code>-<sha7>-<signing>\`. **Existing folders are never overwritten.**

`-DryRun` performs steps 1–3 only (no install, no Gradle).

## build-manifest.json
- `source.commit` and `source.repository`
- `application_id`, `display_name`, `version_name`, `version_code`
- `api_environment.url` / `label`
- `toolchain`: actual Node, npm, Java; pinned Gradle, SDK, NDK
- `dependencies`: expo, react-native, react, expo-modules-core, hermes-compiler, `package_lock_sha256`
- `signing`: mode, certificate SHA-256 and SHA-1, schemes, whether it is the public debug key
- `apk`: file, SHA-256, size, ABIs, SDK levels, permissions
- `build`: timestamps, SHA-256 of the build script and toolchain file

No passwords, keystore paths, API secrets or usernames are recorded.

## Updating a pin
Change `toolchain.json` in its own PR, with the reason. For Gradle, take the SHA-256 from `https://downloads.gradle.org/distributions/gradle-<v>-bin.zip.sha256`. CI (`.github/workflows/android-config.yml`) checks identity, permissions, lockfile pins and secret hygiene on every PR that touches the apps or these scripts.
